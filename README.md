# Evently

**Evently** — мини-приложение для мессенджера MAX, которое помогает находить мероприятия и варианты досуга через персональную ленту рекомендаций.

Основная идея проекта — вместо ручного поиска мероприятий по разным сайтам дать пользователю единую афишу, которая учитывает город, выбранные интересы и действия пользователя.

## 1. Назначение решения

Evently решает задачу поиска досуга и развлечений.

Пользователь может:

- выбрать город;
- выбрать интересующие категории;
- получать персональную ленту мероприятий;
- фильтровать события по категориям;
- просматривать подробную информацию о мероприятии;
- отмечать интересные события;
- взаимодействовать с рекомендациями;
- использовать быстрые сценарии поиска;
- открывать приложение непосредственно внутри MAX.

Система агрегирует мероприятия в единую базу и формирует выдачу с учётом пользовательских предпочтений и истории взаимодействий.

---

## 2. Основной пользовательский сценарий

Основной сценарий:

1. Пользователь открывает Evently в MAX.
2. При первом запуске проходит onboarding и выбирает интересующие категории.
3. Выбирает город.
4. Получает персональные рекомендации.
5. Переходит в ленту мероприятий.
6. Листает карточки событий.
7. При необходимости выбирает конкретную категорию.
8. Открывает подробную информацию о понравившемся событии.
9. Взаимодействует с мероприятиями: просмотр, интерес, скрытие и другие действия.
10. Следующая выдача учитывает накопленные пользовательские предпочтения.

Поддерживаются также быстрые сценарии поиска, например события на сегодня, выходные, бесплатные мероприятия и поиск рядом с пользователем.

# 5. Запуск через Docker

## Требования

Для локального запуска необходимы:

- Docker Engine;
- Docker Compose v2;
- доступ в интернет при первой сборке для загрузки базовых Docker-образов и зависимостей.

Устанавливать Node.js, pnpm или PostgreSQL непосредственно на машину проверяющего не требуется.

## Одна команда для запуска

Из корня репозитория:

```bash
docker compose up --build -d
```

Эта команда:

1. запускает PostgreSQL;
2. собирает контейнер Evently;
3. синхронизирует Prisma-схему;
4. генерирует Prisma Client;
5. создаёт базовые категории;
6. загружает демонстрационные мероприятия;
7. запускает Fastify API;
8. запускает Mini App.

После запуска необходимо подождать несколько секунд, пока завершится инициализация базы.

## 7. Переменные окружения

Пример конфигурации находится в:

```text
.env.example
```

Для стандартного Docker demo создавать `.env` необязательно — используются безопасные значения по умолчанию.

Поддерживаемые параметры:

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `POSTGRES_USER` | пользователь PostgreSQL | `evently` |
| `POSTGRES_PASSWORD` | пароль локальной demo-БД | `evently_dev_password` |
| `POSTGRES_DB` | имя базы | `evently` |
| `EVENTLY_API_PORT` | внешний порт API | `13000` |
| `EVENTLY_WEB_PORT` | внешний порт Mini App | `15173` |
| `EVENTLY_DEFAULT_CITY` | город по умолчанию | `msk` |
| `PARSER_SYNC_INTERVAL_MS` | интервал проверки parser snapshots | `60000` |
| `PARSER_STALE_AFTER_HOURS` | порог устаревания parser snapshot | `7` |
| `IMPORT_API_KEY` | ключ локального demo-import | `docker-demo-import-key` |
| `MAX_BOT_TOKEN` | токен MAX для соответствующей интеграции | пусто |

Значения `evently_dev_password` и `docker-demo-import-key` предназначены только для локального Docker demo и не являются рабочими production-секретами.

Рабочие токены, ключи и пароли в Git-репозиторий не помещаются.

## 9. Внешние сервисы и интеграции

### MAX

Основной продукт работает как Mini App внутри мессенджера MAX.

MAX используется для запуска Mini App и получения данных пользовательского контекста, когда приложение открыто внутри MAX.

Рабочие параметры production-интеграции не включены в публичный исходный код.

Для проверки локального Docker demo MAX не требуется — интерфейс можно открыть непосредственно в браузере.

### Источники мероприятий и parser

Рабочая версия Evently использует отдельный pipeline сбора и нормализации мероприятий.

Parser формирует нормализованные snapshots, после чего backend Evently импортирует их в PostgreSQL через модуль parser-sync.

Runtime-выгрузки парсера имеют большой объём и намеренно не включены в Git-репозиторий.

Для воспроизводимой Docker-проверки используются отдельные синтетические тестовые данные.

### AI / LLM

Архитектура проекта предусматривает AI-подбор мероприятий с использованием локальной LLM через Ollama.

Ollama и веса модели не включены в стандартный Docker demo из-за их размера и аппаратных требований.

Проверка основного локального пользовательского сценария — запуск приложения, onboarding, каталог, лента, категории и карточки мероприятий — не требует Ollama.

## 10. Работа с данными

В рабочем окружении события проходят следующий pipeline:

```text
Источник мероприятий
        │
        ▼
Parser
        │
        ▼
Normalized JSON snapshots
        │
        ▼
parser-sync
        │
        ▼
PostgreSQL
        │
        ▼
Fastify API
        │
        ▼
Recommendation logic
        │
        ▼
Mini App
```

Parser snapshots содержат нормализованные сведения о:

- мероприятии;
- площадке;
- датах проведения;
- изображениях;
- категориях;
- ссылках;
- ценах;
- городе.

Backend выполняет upsert сущностей и поддерживает актуальное состояние PostgreSQL.

# 11. Тестовые данные

Для воспроизводимой Docker-проверки используется отдельный seed:

```text
projects/evently/packages/db/src/docker-demo-seed.ts
```

Он создаёт **12 синтетических демонстрационных мероприятий** для двух городов:

- Москва (`msk`);
- Новосибирск (`nsk`).

В тестовом наборе представлены различные категории, включая:

- концерты;
- театр;
- кино;
- спорт;
- выставки;
- стендап;
- еду;
- семейные мероприятия;
- образование.

Изображения для demo-событий хранятся локально:

```text
projects/evently/apps/miniapp/public/demo/
```

Таким образом, проверка Docker-версии не зависит от доступности сторонних сайтов или внешнего CDN.

Тестовые мероприятия являются синтетическими данными и не должны интерпретироваться как актуальная афиша реальных городов.

# 12. Пошаговый сценарий проверки

## Шаг 1. Запустить проект

Из корня репозитория:

```bash
docker compose up --build -d
```

## Шаг 2. Проверить состояние контейнеров

```bash
docker compose ps
```

Ожидается:

- контейнер PostgreSQL имеет статус `healthy`;
- контейнер Evently имеет статус `Up`.

## Шаг 3. Проверить логи

```bash
docker compose logs --tail=150 evently
```

В логах должны присутствовать этапы инициализации:

```text
Synchronizing PostgreSQL schema
Generating Prisma Client
Seeding categories
Seeding Docker demo events
Starting Evently API
Starting Evently Mini App
```

Также ожидается сообщение:

```text
Docker demo events seeded: 12
```

## Шаг 4. Проверить Mini App

Открыть:

```text
http://localhost:15173
```

Ожидается загрузка интерфейса Evently.

Проверить из командной строки можно так:

```bash
curl -I http://127.0.0.1:15173
```

Ожидаемый HTTP-код:

```text
200
```

## Шаг 5. Проверить API

```bash
curl -sS 'http://127.0.0.1:13000/api/feed/?limit=2&city=msk'
```

Ответ должен содержать JSON с демонстрационными мероприятиями.

## Шаг 6. Проверить фильтр города

Москва:

```bash
curl -sS 'http://127.0.0.1:13000/api/feed/?limit=2&city=msk'
```

Новосибирск:

```bash
curl -sS 'http://127.0.0.1:13000/api/feed/?limit=2&city=nsk'
```

Запрос несуществующего города:

```bash
curl -sS 'http://127.0.0.1:13000/api/feed/?limit=20&city=THIS_CITY_DOES_NOT_EXIST'
```

В последнем случае ожидается пустой список мероприятий.

## Шаг 7. Проверить локальные изображения

```bash
curl -I http://127.0.0.1:15173/demo/concert.svg
```

Ожидаемый HTTP-код:

```text
200
```

## Шаг 8. Проверить основной UI-сценарий

В браузере:

1. открыть Evently;
2. пройти onboarding;
3. выбрать интересующие категории;
4. выбрать город;
5. открыть ленту;
6. пролистать несколько мероприятий;
7. открыть категорию;
8. открыть карточку события;
9. вернуться в ленту.

Ожидаемый результат — приложение продолжает работу без полного перезапуска и отображает события выбранного города.

### Персонализация

Backend хранит пользовательские взаимодействия и использует их при ранжировании дальнейшей выдачи.

### Изображения

В обычной ленте отображаются только события, имеющие изображения.

# 14. Известные ограничения MVP

1. Docker demo использует синтетические мероприятия вместо полного production-датасета.

2. Большой архив parser snapshots и изображений не включён в Git из-за объёма.

3. Доступность и количество реальных мероприятий зависит от источников parser pipeline.

4. Некоторые города могут содержать меньше мероприятий и изображений, чем другие.

5. Локальный Docker demo не воспроизводит инфраструктуру публикации Mini App внутри MAX.

6. Рабочие MAX-токены и другие production-секреты намеренно отсутствуют в репозитории.

7. AI/LLM-инфраструктура через Ollama не входит в стандартный Docker demo.

8. MVP не является системой продажи билетов: переход на покупку выполняется через ссылки соответствующих источников, если они доступны для события.

# 20. Лицензии и источники данных

Evently агрегирует информацию о мероприятиях из внешних источников через отдельный parser pipeline.

Данные Docker demo являются синтетическими и созданы исключительно для воспроизводимой технической проверки MVP.

При дальнейшем развитии проекта необходимо учитывать условия использования и лицензирования каждого подключаемого источника данных.
